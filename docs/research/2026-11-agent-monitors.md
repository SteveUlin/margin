# tools that observe coding-agent sessions: survey for margin

researched 2026-11-08. star counts and last-push dates are from `gh api repos/<r>` (*ran it*) unless marked. "read" = i read the linked page (README, docs) through WebFetch; "search" = only a search-result snippet; "inferred" = my reasoning, not checked against source. GitHub's search API hit its rate limit partway through, so the long tail is thinner than the head.

## the landscape in one paragraph

the field splits into six clusters. **cost/usage meters** (ccusage, Claude-Code-Usage-Monitor) read `~/.claude/projects/*.jsonl` after the fact. **statuslines** (ccstatusline, claude-powerline) render the statusLine stdin JSON. **transcript exporters/viewers** (claude-code-log, simonw's transcripts, claude-code-viewer) render the JSONL as HTML or TUI. **multi-agent managers** (claude-squad, agent-deck, ccmanager, crystal) wrap each agent in tmux plus a worktree and track running/waiting/idle. **multiplexer sidebars** (tmux-agent-sidebar, crmux, cc-deck for Zellij, cc-zjstatus) feed hook events into a status panel. **hook/OTel observability stacks** (disler's dashboard, claude-code-otel) ship events to a server and a web UI. none of these is *bidirectional* the way margin is: they show what Claude did, but none lets sulin flip a default or strike an assumption and have that reach the model through `additionalContext`. the one exception, a native Claude Code mod (claude-code-todo), shows that Claude Code's own plugin panes now overlap margin's niche directly.

## overlap with margin

- **closest in form: cc-deck and cc-zjstatus.** both put hook-fed Claude state into Zellij. cc-deck is the only other Zellij *sidebar* (*read*). both are one-way and track status across sessions. neither has a plan, questions, assumptions, or anything flowing back to Claude.
- **closest in content: tmux-agent-sidebar.** it shows prompts, tool calls, response previews, task progress, subagent trees and wait reasons per pane (*read*), which is a superset of margin's "live tool activity" strip. it runs on tmux, not Zellij, and it is also read-only.
- **closest in concept: claude-code-todo (native mod).** it has a pane beside the chat, a band above the prompt, and a tool the model writes through (*read*). that is margin's core loop (Claude keeps a structured list current, sulin sees it beside the chat) built on Claude Code's own plugin API, with no Zellij and no hooks. it is far thinner (a checklist only), but it shows the platform now hosts margin's category natively.
- **agent-deck's conductor and transition notifier** parallel margin's stale-pane nudge. both are hook-driven "wake the agent when a watched state changes" loops (*read*).
- **margin is unique on:** bidirectional state (questions with defaults, strikeable assumptions, diff verdicts delivered back via UserPromptSubmit/PostToolUse `additionalContext`), stable component ids so a tick survives a rewrite, and feeds (scripts that keep a panel current without Claude). no surveyed tool does any of the three (*inferred* from the READMEs i read; i didn't read every repo's source).
- **where others are better:** multi-session overview and attention routing (cc-deck smart attend, agent-deck, crmux); cost, context and rate-limit numbers (statusline tools, ccusage); full transcript rendering (claude-code-log); desktop/phone notifications on permission or finish (tmux-agent-sidebar, agent-deck).

## ideas to borrow

1. **register margin as (or tee into) the statusLine command.** this is crmux's trick (*read*). the statusLine JSON carries `context_window.used_percentage`, `cost.total_cost_usd`, `rate_limits.five_hour/seven_day` with `resets_at`, `prompt_cache.warm/expires_at`, `session_name` and `prompt_id`, and it arrives per assistant message with a 300 ms debounce (*read*, statusline docs). margin gets a header line ("62% ctx · $1.40 · 5h 41% resets 18:20 · cache warm 3m") for free, and `session_name` gives the pane a human title. catch: only one statusLine command exists, so `margin statusline` has to record the JSON and then exec the user's real statusline and pass its output through (*inferred*).
2. **attention states with timeouts, not just events.** cc-deck moves Working to Done after 5 min with no hook events, because `Stop` doesn't always fire, then Done to Idle to Paused (*read*). margin should also hook `Notification` and `PermissionRequest` and show a loud "blocked on you: permission for Bash(rm …)" row. that is the highest-value thing a sidecar can say, and margin doesn't hook either event today (*read* `hooks/settings.example.json`: only UserPromptSubmit, Pre/PostToolUse, Stop, SessionStart).
3. **push a glyph into zjstatus via `zellij pipe`.** cc-zjstatus does this (*read*). margin's state (open questions count, blocked, stale) then shows in the tab bar even when the pane is closed or on another tab. this is cheap and complements margin without competing with it.
4. **mirror Claude's native task list and plan file instead of nudging.** TodoWrite/TaskCreate calls appear in PreToolUse input and in the transcript, and plan-mode plans land in plan files (crmux's `get-plans` lists them, *read*). margin could ingest those into its plan component automatically, so Claude stops writing the plan twice. that would cut the "N tool calls since you last wrote to your pane" nudges, which fire even in subagents that own no pane (*observed* in this run).
5. **read `transcript_path` for a response preview and subagent tree.** every hook payload carries the transcript path. tailing the last assistant text block and Agent/Task spawns gives tmux-agent-sidebar's "response preview" and "subagent tree" (*read*), and claude-code-log shows the JSONL has enough structure for both (*read*).
6. **decide about native Claude Code mods.** the function-hook API offers a docked `Pane`, an `AbovePrompt` band, `$.state`, model-callable tools and `prompt.context` (*read*, plugin-authoring `reference.md`). that covers margin's render, its tool, and its context injection without Zellij or shell hooks, and it renders on desktop, mobile and VS Code too. the cheap first step is a band mod that reads margin's store and shows "2 questions · 1 assumption struck · plan 4/7", with margin's Rust pane staying the rich view (*inferred* design; the API is early access and moves between releases).
7. **forward attention to ntfy.** tmux-agent-sidebar sends desktop notifications on finish, permission and error, and agent-deck escalates to chat apps (*read*). margin could fire ntfy when a question with no default has waited N minutes, or when Claude is blocked on permission, using the attention states from idea 2 as the trigger.
8. **OTel `tool_decision` and `api_error` as a feed, later.** OTel events carry `prompt.id` and `tool_use_id`, so you can group a turn's tool results, rejections and API errors (*read*). a tiny local OTLP http/json receiver would feed a "turn ledger" with durations and rejects. it's lower priority than ideas 1–5, because hooks already deliver most of this with less setup (*inferred*).
9. **multi-session index ("smart attend" lite).** margin already links session to pane. a `margin ls --attention` sorted by blocked, then open questions, then stale (cc-deck's priority order, *read*) turns it into the "which Claude needs me" answer across Zellij tabs.
