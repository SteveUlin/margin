# task tracking for a claude code workflow: built-in tools, beads, others, and margin

researched 2026-11-08 against claude code 2.1.319 (`claude --version`, ran it).

## answer first

margin should stay its own store (option c), plus two cheap additions:

1. **a passive mirror** of claude code's task tools for sessions that have them. the mirror reads PreToolUse/PostToolUse on `TaskCreate`/`TaskUpdate`, or the `TaskCreated`/`TaskCompleted` hooks, and costs zero model tool calls.
2. **hook-derived lanes** for subagents (`SubagentStart`/`SubagentStop` plus `agent_id` on every tool hook). subagents write to the pane through the CLI only when they own a real multi-step plan.

don't move margin onto beads. borrow three of its ideas instead: a `ready` query, atomic claim, and a `waits-for` edge for fan-in.

the main reason: on margin's model (opus 5.5) claude code has **removed its task tools by default**. anthropic gave two reasons: newer models track work without a checklist, and the tools' definitions and reminders cost context. codex made the same move with `update_plan` over "plan drift" between competing surfaces. margin already is the one plan surface that sulin can see and steer, so it should stay the single source of truth.

## findings

### 1. claude code's task tools

- **four tools replaced TodoWrite.** 2.1.16 added a "new task management system, including new capabilities like dependency tracking"; 2.1.19 added `CLAUDE_CODE_ENABLE_TASKS` (false keeps the old system). *read*: [CHANGELOG](https://raw.githubusercontent.com/anthropics/claude-code/main/CHANGELOG.md). TodoWrite comes back only with `CLAUDE_CODE_ENABLE_TASKS=0`, and only in sessions that have task tools at all. *read*: [tools-reference](https://code.claude.com/docs/en/tools-reference.md), tool table.
- **they're off by default on new models.** the tools ship by default "only on Opus 4.7, Sonnet 4.6, Haiku 4.5, and earlier models". anthropic's stated rationale: "On newer models, Claude keeps track of multi-step work without a written checklist, and the tools' definitions and reminders take up context." opt back in with `CLAUDE_CODE_ENABLE_TODO_TOOLS=1`, `--allowedTools TaskCreate`, or `--tools`. **background sessions (agent view) and cloud sessions get the tools on every model.** *read*: [tools-reference § Task tool availability](https://code.claude.com/docs/en/tools-reference.md). changelog: 2.1.233 removed them on "Opus 4.8, Sonnet 5, Fable 5, Mythos 5, and newer"; 2.1.268 narrowed the list to Claude 3.x / Opus 4.0–4.7 / Sonnet 4.0–4.6 / Haiku 4.5. *read*: CHANGELOG. this explains why the session has no TodoWrite/TaskCreate: it isn't a misconfiguration. this machine has no `~/.claude/tasks/` directory (*ran* `ls ~/.claude`), which fits.
- **storage.** `~/.claude/tasks/` holds "Task lists written by the task tools, one directory per list". `~/.claude/todos/` is legacy and "No longer written". *read*: [claude-directory](https://code.claude.com/docs/en/claude-directory.md). tasks "persist across context compactions", and `CLAUDE_CODE_TASK_LIST_ID=my-project claude` shares a named list across sessions. *read*: [interactive-mode § Task list](https://code.claude.com/docs/en/interactive-mode). an agent team's list lives at `~/.claude/tasks/{team-name}/` (team name is `session-` + 8 chars of the session id) and stays on disk after the session. *read*: [agent-teams](https://code.claude.com/docs/en/agent-teams.md). i didn't inspect the per-task file format because no files exist here.
- **fields.** `TaskCreate` takes `subject`, `description` and `activeForm`. `TaskUpdate` takes `taskId`, `status` (pending/in_progress/completed/deleted), plus deps and details. the stream shows the raw model input, which is sometimes `id`/`task_id`/`active_form`, so read it defensively. *read*: [agent-sdk/todo-tracking](https://code.claude.com/docs/en/agent-sdk/todo-tracking.md). the team docs describe three states plus blocked-by-dependency, with auto-unblock on completion. *read*: agent-teams.
- **sharing.** "A subagent has the task-tracking tools only when your session has them". an in-process teammate gets them when the session has them, and a split-pane teammate inherits `--tools` and deny rules but not an exported env var. *read*: tools-reference § subagents and agent teams. the docs say subagents can call the tools, not that they share the parent's list, so whether a subagent writes into the parent's list is *not verified*. the team list is explicitly shared: teammates self-claim "the next unassigned, unblocked task" with file locking. known limitation: "Task status can lag". *read*: agent-teams. agent teams themselves need `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1`.
- **hooks.** `TaskCreated` fires on `TaskCreate`. `TaskCompleted` fires on `TaskUpdate`→completed, or when a teammate ends its turn with in-progress tasks. neither takes a matcher. both payloads carry the common fields plus `task_id`, `task_subject`, optional `task_description`, `teammate_name`, deprecated `team_name`, and `agent_id` (≥2.1.290). exit 2 or `{"decision":"block"}` on TaskCreated deletes the task and returns the reason to claude. exit 2 on TaskCompleted blocks completion. there is **no task-updated hook** for other status changes (in_progress, deleted), so a mirror needs PreToolUse/PostToolUse on `TaskUpdate` for those. "In a session without the Task tools, this event doesn't fire." *read*: [hooks § TaskCreated/TaskCompleted](https://code.claude.com/docs/en/hooks.md). added in 2.1.33 (TaskCompleted, TeammateIdle) and 2.1.84 (TaskCreated). *read*: CHANGELOG.
- **subagent hooks.** `SubagentStart` (carries `agent_id`, `agent_type`) can inject `additionalContext` into the subagent. `SubagentStop` carries `agent_transcript_path` and `last_assistant_message`. tool hooks inside a subagent carry `agent_id`/`agent_type`. *read*: hooks.md.

### 2. beads

- **what it is.** "Distributed graph issue tracker for AI agents, powered by Dolt". it "replaces messy markdown plans with a dependency-aware graph" for long-horizon work. the repo moved to `gastownhall/beads` and is the substrate under yegge's Gas Town orchestrator. *read*: [README](https://raw.githubusercontent.com/gastownhall/beads/main/README.md); [yegge-ai.pages.dev](https://yegge-ai.pages.dev/code).
- **data model.** issues have hash ids (`bd-a1b2`) and hierarchical children (`bd-a3f8.1.1`), priority, type, and assignee. dependency types: blocking `blocks`, `parent-child`, `conditional-blocks` and `waits-for` ("B waits for all of A's children", fan-out aggregation); non-blocking `related`, `discovered-from`, `tracks`, `caused-by`, and more. `bd ready` lists issues whose blocking deps are all closed, and `bd update --claim` claims atomically. extras: message issues with threads, `bd remember` memories, "compaction: semantic memory decay" of old closed tasks. *read*: README, [dependencies.md](https://raw.githubusercontent.com/gastownhall/beads/main/docs/core-concepts/dependencies.md).
- **storage.** an embedded Dolt db in `.beads/embeddeddolt/` with a single writer, or `dolt sql-server` for concurrent writers. `issues.jsonl` "is an export ... not the source of truth". sync runs over `refs/dolt/data` on a git remote. git-free/jj use goes through `BEADS_DIR` + `bd init --stealth`, which the README names Jujutsu for. *read*: README.
- **claude code integration.** `bd setup claude` installs a SessionStart hook running `bd prime --hook-json`, which injects "~1-2k tokens of workflow context", re-fires after compaction, and adds a minimal CLAUDE.md section. a plugin and an MCP server (`beads-mcp`) also exist. agents are told "Do not use markdown TODO lists". *read*: [ide-setup.md](https://raw.githubusercontent.com/gastownhall/beads/main/docs/getting-started/ide-setup.md).
- **status.** 28,609 stars, last pushed 2026-11-09 (*ran* GitHub API on gastownhall/beads). npm `@beads/bd` latest is 1.3.4, published 2026-11-04 (*ran* npm registry). started oct 2025 and passed 20k stars by apr 2026 (*read*, secondary: [dark-factory-kb](https://dark-factory-kb.pages.dev/steve-yegge-beads.html)). it's actively developed and widely starred. the long security/HTTP sections in the README say the surface is still churning (schema migrations, an experimental HTTP backend) (*inferred*).

### 3. other trackers

- **Task Master** (`eyaltoledano/claude-task-master`): parses a PRD into `tasks.json` tasks with deps and subtasks, and calls its own models (main/research/fallback API keys). it runs as an MCP server (`claude mcp add taskmaster-ai`) or a CLI. 28,327 stars, but the last push was 2026-04-28 and the last npm release was 0.43.1 on 2026-03-31, so it's stagnant (*ran* GitHub API/npm; *read* [README](https://github.com/eyaltoledano/claude-task-master)).
- **Backlog.md** (`MrLesk/Backlog.md`): one markdown file per task in the repo, with acceptance criteria, milestones, deps, a terminal kanban and a web UI. it's built around three human review checkpoints (spec, plan, code; "one task = one context window = one PR"). 7,318 stars, pushed 2026-11-04, v1.55.3 (*ran* API/npm; *read* [README](https://github.com/MrLesk/Backlog.md)). its philosophy sits closest to margin's: human attention is the bottleneck, so review the plan before the code.
- **codex `update_plan`**: ordered steps, statuses pending/in_progress/completed, "exactly one item in_progress". reportedly made opt-in by openai/codex PR #41744 on 2026-08-31 (`tools.update_plan.enabled`), because with Linear/Jira MCP "the Codex plan panel shows one state; the Linear board shows another". *read*, secondary, PR not verified: [danielvaughan blog](https://codex.danielvaughan.com/2026/08/31/codex-cli-update-plan-tool-opt-in-external-planning-competing-surfaces/).
- **kiro**: specs as requirements → design → `tasks.md`. kiro builds a dependency graph from `tasks.md` and runs independent tasks concurrently in waves. *read* (search summary): [kiro.dev/docs/specs](https://kiro.dev/docs/specs.md). **cursor**: agent to-dos since 1.2 (jul 2025) and plan-mode plans saved under `.cursor/plans/`. *read*, secondary: [alternativeto](https://alternativeto.net/news/2025/7/cursor-1-2-adds-agent-generated-to-dos-queued-tasks-and-merge-conflict-help).
- **linear / github issues via MCP**: these are durable team-visible backlogs. their cost is the competing-surface drift that codex hit, and every MCP tool schema adds context (*inferred* from the codex rationale and claude code's own stated reason).
- **the pattern**: the industry primitive is converging on "small model-owned plan + typed deps + a ready query". two vendors have now made the built-in checklist opt-in on strong models, both citing context cost and duplicated surfaces (*inferred* from the two items above). margin's `docs/landscape.md` already lists "competing surfaces → one canonical plan; mirror TodoWrite rather than run a parallel list" (*read*). that advice predates the default-off change, so it needs revising: there's usually nothing to mirror now.

## recommendation for margin

**(c) margin as the single store, with a passive (a) for sessions that have task tools, and beads ideas rather than beads.**

- **single source of truth.** on opus 5.5 the task tools don't exist unless someone opts in. turning them on re-creates exactly the two-surface drift that codex removed `update_plan` over, and pays the schema + reminder tax anthropic cited. keep margin canonical. where the tools do appear (background/agent-view sessions, which get them on every model, teams, older models, SDK workers), mirror them **read-only** into a `claude tasks` section from PreToolUse/PostToolUse on `TaskCreate|TaskUpdate`. those hooks carry `tool_input`, so the mirror sees every status change, which `TaskCreated`/`TaskCompleted` alone miss. the mirror costs no model calls and gives sulin one view. don't write back into `~/.claude/tasks/`: its format is undocumented, and claude wouldn't notice the change anyway.
- **subagents and fan-outs.** build the work overview from hooks, not from subagent CLI writes. `SubagentStart` (agent_id, agent_type) opens a lane under the parent's current step, tool hooks with `agent_id` keep "what it's doing now" current, and `SubagentStop` (`last_assistant_message`) closes it. that's free in tokens and can't drift. the parent writes the fan-out section once ("review PR: 4 reviewers") with a fan-in step. add a beads-style `waits-for` edge, done when all children are done, so the graph shows the aggregation. let a subagent write its own sub-plan via the CLI only when it runs long. `SubagentStart.additionalContext` can hand it the artifact and section id so it doesn't have to discover them.
- **survival across compaction/sessions.** margin's store is on disk, and the existing SessionStart(`compact`|`resume`) read-back already does what `bd prime` does, aimed at the plan sulin can strike. that matches the task tools' "persist across compaction" with no extra machinery. for cross-session backlog (weeks of work), beads or Backlog.md fits better than margin. if sulin wants that, add a **feed** that renders `bd ready --json` into a panel rather than making beads margin's store.
- **cost.** a margin write is one Bash call, the same as a TaskUpdate. hook-derived activity is zero. beads adds ~1-2k tokens per session start plus a Dolt database. MCP trackers add schemas to every request. the cheapest correct design writes the plan when its *shape* changes and lets hooks report *progress* (*inferred*).
- **seeing and steering.** none of the alternatives gives sulin margin's affordances (strike an assumption, flip a default, mark next/skip with the decision delivered back). claude code's view is 5 rows under Ctrl+T, and beads is CLI-first. Backlog.md's review-checkpoint framing is worth stealing for wording; its storage isn't.

borrow from beads: `margin ready` (open steps whose `after` deps are all done) for the "plans next" column, atomic claim when two agents could take one step, and hash-style ids if several processes create steps concurrently.
